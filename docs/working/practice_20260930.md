# Próba tablicy prowadzonej rozmową

Cel: przeprowadzić jedną rozmowę nad trzema projektami, podczas gdy wykonawcy
pracują w tle, bez utraty właściciela, pytania lub późniejszej aktualizacji.

## Uruchomienie

W katalogu projektu: `node scripts/local-pilot.mjs start`.
Panel: http://127.0.0.1:45441. Hasło do logowania Manager kopiuje
`node scripts/local-pilot.mjs copy-password`; nie wyświetlamy go w terminalu.
Start nie resetuje danych. Na koniec `node scripts/local-pilot.mjs stop`.

Do rozpoczęcia rozmowy wystarczy powiedzieć: „Zaczynamy praktyczny test tablicy”.
Orkiestrator czyta `AGENTS.md`, sprawdza usługi i pobiera kolejki przez CLI.
Nie trzeba każdorazowo otwierać panelu — jest podglądem i alternatywnym miejscem odpowiedzi.

Przygotowane dane wejściowe są w `examples/practice/`: odpowiedź API, profile
druku i twierdzenie o fikcyjnym produkcie. Konta wykonawców mają osobne prywatne
profile: `tmp/practice/client-api.json`, `client-printer.json`, `client-facts.json`.
Wykonawca podaje właściwą ścieżkę w `KANBAN_PROFILE` i przejmuje swoją kartę.
Nie dostaje hasła człowieka ani dostępu do pozostałych projektów.

## Przebieg i oczekiwane zachowanie

1. **Praca w tle:** wybierzmy kartę z każdego projektu. Orkiestrator przypisuje
   wykonawcę i zapisuje następny krok. W próbie korzystamy z fikcyjnych danych,
   bez dostępu do rzeczywistych repozytoriów.
2. **Jedno pytanie:** wykonawca publikuje `decision` lub `confirmation`, z krótkim
   kontekstem i pytaniem. „Dalej” przedstawia jedną sprawę. Inne wyniki czekają.
3. **Odpowiedź:** użytkownik odpowiada własnymi słowami. Orkiestrator zapisuje tę
   odpowiedź z numerem wersji, przekazuje ją wykonawcy; karta nie kończy się sama.
4. **Odłożenie:** użytkownik odkłada inną sprawę z powodem i warunkiem/terminem.
   Znika z bieżącej rozmowy. Upływ terminu sygnalizuje możliwość powrotu,
   ale nie uruchamia tematu bez decyzji.
5. **Odbiór wyniku:** wykonawca kończy kartę i publikuje informację. Orkiestrator
   przedstawia dowody i ograniczenia; dopiero wtedy oznacza tę wersję jako omówioną.
6. **Nowa wiadomość:** wykonawca publikuje późniejsze ustalenie. Karta wraca do
   rozmowy. Stare potwierdzenie nie ukrywa nowej wersji.
7. **Przerwa:** zatrzymajmy i uruchommy lokalne środowisko. Właściciele, pytania,
   odpowiedzi, historia i odłożenia muszą pozostać.

## Skrót komend dla orkiestratora

```bash
node scripts/conversation.mjs next
node scripts/conversation.mjs next work
node scripts/conversation.mjs task INF-900
node scripts/conversation.mjs claim INF-900
node scripts/conversation.mjs publish INF-900 --revision 0 --kind decision --summary "Synthetic sources disagree" --question "Use source A or B?"
```

Numer karty i wersję zawsze pobieraj z aktualnego stanu. Przykładu publikacji nie
uruchamiaj w ciemno na karcie, która ma już pytanie. `answer` i `discuss` wymagają
`--human`, konkretnej wersji i faktycznej wypowiedzi/omówienia użytkownika.

## Granice próby

Tablica nie uruchamia modeli i nie synchronizuje ich czatów. Delegowanie wykonuje
orkiestrator, który zapisuje wyniki w kartach. Panel ma angielskie etykiety; rozmowa
jest po polsku. Panel używa zależności CDN i wymaga internetu przy pierwszym otwarciu.
Lokalne dane testowe przeżywają restart, ale nie są kopią zapasową.

Odbiór jest zaliczony, gdy każdy z siedmiu kroków przejdzie w rozmowie bez ręcznego
poprawiania bazy, zgubionych pytań i przedstawienia fikcyjnej zgody jako prawdziwej.
